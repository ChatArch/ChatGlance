# ChatGlance Site Architecture

ChatGlance is a Python package plus repository-side operations records for the ChatArch Glance website. It is not an npm frontend project.

## What ChatGlance owns

ChatGlance owns the reproducible source and scripts that produce the live site's Glance configuration artifacts:

- `src/chatglance/`: Python package code for rendering Glance page YAML, inline HTML widgets, config patching, validation helpers, and runtime/systemd helpers.
- `scripts/refresh-projects-page.sh`: refreshes ChatArch project inventory data, renders the `项目` page, validates a candidate `glance.yml`, backs up the previous live files, and replaces the generated artifacts.
- `scripts/refresh-server-status.sh`: refreshes server-status data, renders the `服务器` page, validates a candidate `glance.yml`, backs up the previous live files, and replaces generated artifacts.
- `docs/` and `examples/`: deployment contracts, quick start, project-page contract, infra/server-page contract, and sanitized runtime config examples.

## What ChatGlance does not own

- It does not reimplement the upstream Glance server.
- It does not use npm or `package.json` to build the website.
- It does not commit live secrets, auth config, tokens, cookies, proxy settings, or raw runtime data.
- It does not clone/build/run arbitrary ChatArch repositories while refreshing the project page.

## Runtime split

The live website is the combination of:

1. **Upstream Glance binary**: serves the dashboard from `glance.yml`.
2. **ChatGlance-generated config/pages**: Python code renders/patches Glance YAML and HTML widgets.
3. **Runtime data snapshots**: JSON/YAML files under the live runtime directory, refreshed by scripts.
4. **User-level service wrapper**: systemd `--user` units start/restart Glance; refresh scripts do not manage lifecycle by default.
5. **Public entry**: reverse proxy/auth exposes the site externally.

Typical live runtime layout:

```text
~/.chatarch/glance/
  bin/glance                         # upstream Glance Go binary
  config/glance.yml                  # live dashboard config
  config/project-category-overrides.json
  config/server-inventory.yml        # live-only, secret-free inventory labels
  config/backups/                    # generated backups
  data/chatarch-projects.json        # generated project data
  data/projects-page.yml             # generated 项目 page
  data/server-status.json            # generated server snapshot
  data/server-page.yml               # generated 服务器 page
```

## Source-data contract

The source repository must be able to explain and regenerate the website's generated pieces without depending on undocumented local edits:

- Source code defines renderers and safe config replacement behavior.
- Runtime data is generated by scripts and kept out of git.
- Reviewed runtime-only categorization, such as project category overrides, lives in runtime config and can be represented by sanitized examples/docs.
- Every refresh must validate the candidate config before replacement.
- Service restart/reload is an explicit outer action after refresh, not hidden inside data generation.

## Packaging

ChatGlance is packaged as a Python package:

```toml
[project]
name = "ChatGlance"

[project.scripts]
chatglance = "chatglance.cli:main"
```

The package can be installed into the server's ChatArch virtualenv. There is no npm build step for ChatGlance itself.
