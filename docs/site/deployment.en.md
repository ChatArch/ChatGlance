# Self-contained runtime (operator-reviewed)

This applies to a wheel **containing** portable support, not an already published PyPI release or a production migration. Supported service surface: POSIX/Linux user systemd; operators select a Go binary for the reviewed platform and architecture. The maintained ChatArch/glance fork owns optional login and page features. Five layers: shareable source, installed wheel, verified Go binary, private runtime config/snapshots, optional OS/nginx entries. No checkout dependency after installation.

```text
<CHATARCH_HOME>/
  envs/                         typed ChatEnv profiles
  glance/
    bin/glance                  verified Go fork, not bundled in PyPI
    bin/glance.provenance.json  tag/revision, observed version and both SHA256
    config/glance.yml           loopback 127.0.0.1:8080 starter
    config/server-inventory.yml hosts: [], no automatic SSH
    config/site-services.yml    empty site inventory
    config/reverse-proxy.example.conf  reviewed nginx example
    data/                        empty project/server/site/account snapshots
    scripts/{start,install,refresh}.sh  thin wheel-provided CLI wrappers
    logs/  staging/              shared refresh lock under logs/
<review-dir>/chatglance-portable*.service|timer  not registered by default
```

## Configure and verify

Install a reviewed wheel in an isolated Python environment and choose a private `CHATARCH_HOME` (such as `$PWD/isolated-home`). Run `chatenv status`, `chatenv init -t chatglance -i`, then interactively enter `CHATGLANCE_LOGIN_USER` (email supported), `CHATGLANCE_LOGIN_SECRET` (Go-compatible standard base64 decoding to **exactly 64 bytes**) and bcrypt `CHATGLANCE_LOGIN_PASSWORD_HASH` with `chatenv set -i`. Never pass values in CLI arguments or scripts. `chatenv list` / `chatenv use -t chatglance PROFILE` activate an existing typed profile. Omit `--with-auth` without login; an existing unauthenticated config cannot be silently upgraded: review a fresh runtime candidate instead.

```bash
chatglance runtime paths
chatglance runtime init --with-auth
chatglance runtime install-binary --archive reviewed.tar.gz --sha256 EXPECTED_SHA256 --binary-version chatarch-vX.Y.Z+40_LOWERCASE_HEX
chatglance runtime render-portable --page projects --interval 30min --output-dir ./review-units
```

Replace the illustrated version with the binary's **exact** `--version` output (`chatarch-vMAJOR.MINOR.PATCH+40-lowercase-hex`). The locally SHA256-approved tar must contain exactly one regular `glance` member. Installation runs its staged `--version` with a timeout, checks the expected value, and records archive/binary SHA256 without replacing unknown existing files. No latest download. `chatglance refresh` uses Go `config:validate` in the same typed environment; the operator still needs real binary and guest/auth acceptance. The starter has only a clock home; review inventories and add the intended pages before refreshing. Empty hosts never trigger SSH. Legacy `runtime maintain` is optional; no mandatory maintenance timer.

## Explicit operation and activation boundary

`chatglance runtime serve` explicitly starts the installed Go server in the foreground; login secrets enter only the child environment, resolved from process env first, then active typed ChatEnv. `chatglance refresh projects --runtime-home DIR --service-name chatglance-portable.service` uses the native shared lock, validates/publishes, and restarts **its own named service only when content changes**. `render-portable` without page/interval options uses typed `CHATGLANCE_REFRESH_PAGES` (space/comma-separated) and `CHATGLANCE_REFRESH_INTERVAL`; no timer is generated by default. Only projects/servers/sites are supported, never automatic account scans/card redemption. `CHATGLANCE_PROJECTS_OWNER` sets the owner, overridden by explicit `--projects-owner` / `--owner`.

For controls, first enable Go login and a private `/account-limits` page; set HTTPS `CHATGLANCE_PUBLIC_ORIGIN` and `CHATGLANCE_CONTROL_PORT` (default 5679). Explicitly use `chatglance runtime render-portable --controls --output-dir ./review-units` or `chatglance runtime controls`. Controls use Go sessions and fail closed without complete credentials. Review the example same-origin nginx `/_chatglance/reset-policy/` route, login cookies and old `/项目` redirect; configure real TLS/hostname before external exposure. No nginx install/reload. CRS continues consuming its existing profile and GitHub the shared resolver; no new token store.

**After review only**, run `systemd-analyze --user verify ./review-units/*`; an operator can manually place the new units in their user systemd directory and separately decide on `systemctl --user daemon-reload`, `enable`, and `start`. `render-portable` never registers/starts services; legacy `runtime install-systemd` is a separate mutating command, not automatic migration. Confirm real flags with `chatglance --tree` / `chatglance --tree-brief`; repository-root `docs/cli-tree.md` contains the tested commented trees. Release, production migration and external deployment require separate authorization.

**Operator-only example after review; ChatGlance does not execute this:**

```bash
systemd-analyze --user verify ./review-units/*
mkdir -p "$HOME/.config/systemd/user"
install -m 0644 ./review-units/chatglance-portable.service "$HOME/.config/systemd/user/"
# Only when --page was reviewed: install both refresh.service and refresh.timer
install -m 0644 ./review-units/chatglance-portable-refresh.service ./review-units/chatglance-portable-refresh.timer "$HOME/.config/systemd/user/"
# Only with --controls: separately install controls.service
systemctl --user daemon-reload
systemctl --user enable --now chatglance-portable.service
systemctl --user enable --now chatglance-portable-refresh.timer
# Optional: systemctl --user enable --now chatglance-portable-controls.service
```
